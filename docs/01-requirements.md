# 需求边界说明

## 1. 服务定位

为智能体（上游为星辰工作流及其他对话式调用方）提供**唯一职责**的无状态能力：
接收一段完整 HTML（含内联 CSS），在受控环境中**原样**渲染为简历样式的 PDF，并以下载链接或二进制流返回。

## 2. 核心需求（必须实现）

| 编号 | 需求 | 可验收的判定方式 |
| --- | --- | --- |
| R1 | 接收完整 HTML（含内联 `<style>` / `style` 属性）渲染为 PDF | 提交黄金样例 HTML，产出 PDF 可打开、非空白 |
| R2 | **不修改** 输入 HTML 的结构、文本、样式 | 渲染前对 HTML 取 SHA-256 并记录；代码中不存在任何对 HTML 的注入/替换/补全路径；文档给出「零改写」约束与对应测试 |
| R3 | 高保真：浏览器可见效果与 PDF 一致 | 黄金样例集合（Flex/Grid/分页/表格/CJK）在 Chromium 与 PDF 中版面一致，人工比对无结构性偏差 |
| R4 | 请求参数可配置：HTML 来源与大小上限、页面尺寸、边距、超时、输出形态、文件名 | 参数契约见 `03-api-contract.md`，每个参数都有越界用例 |
| R5 | 响应形态：JSON（含可下载 URL）或 PDF 二进制流 | 两种 `Accept` 均返回正确 `Content-Type` 与状态码 |
| R6 | 统一错误码表 | 所有非 2xx 响应结构一致，且错误码取自 `03-api-contract.md` 的封闭集合 |
| R7 | 限流与调用限制 | 超配额返回 429/503 并带 `Retry-After`，压测可复现 |
| R8 | 参数校验 | 非法 JSON、空 HTML、超长 HTML、非法页面尺寸/边距/超时均被拒且错误码准确 |
| R9 | 统一异常处理 | 任意内部异常对外只呈现稳定错误码，不泄漏堆栈、文件路径与库版本 |
| R10 | 渲染超时控制 | 超时用例稳定返回 504，且不残留渲染进程与临时文件 |
| R11 | 并发控制 | 并发上限可配置；达到上限时排队或快速失败，行为可预测 |
| R12 | 渲染资源隔离 | 渲染在受控进程/上下文边界内执行，容器施加内存、CPU、PID 限额；异常渲染不影响 API 存活性 |
| R13 | 临时文件清理 | 请求级临时目录与过期产物按 TTL 清理，进程重启后可回收遗留文件 |
| R14 | 网络与本地资源访问限制 | 默认**零外部网络**、禁止 `file://` 读取宿主文件；有测试用例证明 SSRF 与本地文件探测均失败 |
| R15 | 日志与配置管理 | 全部配置项来自环境变量并有默认值与说明；结构化日志含 `request_id`，**不记录 HTML 正文** |
| R16 | 健康检查与可观测性 | `/healthz`、`/readyz`、`/metrics` 可用；指标覆盖请求量、时延、并发、失败分类 |
| R17 | 必要测试 | 单元 + 集成 + 冒烟 + 并发/超时/安全用例，全部可一键执行 |
| R18 | 代码规范 | 分层清晰、命名一致、注释适度；ruff（lint+format）+ mypy 通过；按 `00-recon-and-decisions.md` 第 2.3 节落地《手册》可迁移内核 |
| R19 | 向后兼容 | 现有 `POST /render` 调用方不受影响（详见 `03-api-contract.md` 兼容策略） |
| R20 | 交付物 | 源码、开发文档、OpenAPI 3.0 Schema、测试结果、验收说明 |

## 3. 明确不做（Out of Scope）

以下能力**本服务不提供**，且不得在实现中以「顺手」为名加入：

1. **不做任何 HTML 编辑类能力**：不注入、不重写、不补全、不美化、不压缩、不格式化、不新增或修改 CSS/结构/文案，即使输入 HTML 有明显缺陷（缺 `</html>`、样式冲突、乱码文本）也照原样渲染。
2. **不做 HTML 净化 / sanitize**：净化必然改写输入。安全边界靠「隔离执行 + 零网络 + 禁用 JS」达成，而非改写内容。
3. **不做模板系统**：不提供简历模板、主题、字体方案或占位符替换；输入即最终文档。
4. **不做内容理解与生成**：不解析简历语义、不提取字段、不做 ATS 评分、不做内容审核、不做脱敏。
5. **不做可视化编辑器 / 预览 UI**：只提供 API。
6. **不执行 JavaScript**：渲染上下文强制关闭 JS（这是安全决策，非保真妥协）；依赖 JS 才能成型的 HTML 不在支持范围内，且**不会**被告知可通过我们脚本化补足。
7. **不做远程资源抓取**：默认不加载外链字体、图片、样式；智能体需把资源内联（`data:` URI 或内嵌 CSS）。
8. **不做 PDF 后处理**：不加水印、不合并、不拆分、不加密、不签名、不压缩图片、不改元数据（v1 明确不做，避免触碰「不得美化」的红线）。
9. **不做异步任务队列 / 回调通知**：v1 为同步接口；长文档能力靠超时参数解决，不做 `202 + 轮询` 模式。
10. **不做多租户计费与配额结算**：仅做技术限流，不做计量收费。
11. **不做文档格式转换**：不接收 DOCX/Markdown/图片/URL 作为输入源，只接收 HTML 字符串。
12. **不做输入 HTML 的持久化归档**：不长期保存用户 HTML 正文。

## 4. 关键约束与假设

**约束**

- 输入必须是完整 HTML 文档字符串（`text/html`），或指向受信任内网地址的 `html_url`（默认关闭，见 D1/D3 决策）。
- 输出目标形态是**简历**（A4 竖版、单页或多页、中文为主），但不硬编码任何简历排版规则。
- 单实例服务，无共享状态；可水平扩展（产物通过共享卷或对象存储对齐）。

**假设（若与实际不符请纠正，会影响部分设计）**

- A1：调用方为**单租户**，鉴权采用单一 API Key，限流按 Key/IP 维度。
- A2：绝大多数请求为单页简历，HTML 体积 < 512KB。
- A3：HTML 中的字体/图片由调用方内联，无需服务端拉取外网。
- A4：现有 `POST /render` 可能已上线，需保留兼容。
- A5：部署目标为 Docker 容器（云主机或 K8s），具备持久卷或可接受产物丢失。

## 5. 验收口径

整体验收以 `06-test-and-acceptance.md` 为准，其核心量化门禁为：

- 渲染成功率：黄金样例集合 100% 通过且 PDF 非空白；
- 时延：单页简历 P95 < 3s（4 vCPU / 4GB 容器，并发 4）；
- 稳定性：连续 20 并发 × 5 分钟无 5xx（配额内）、无 OOM、进程数不增长；
- 隔离性：SSRF 与本地文件读取用例 100% 被阻断；
- 一致性：错误响应 100% 命中错误码表，无堆栈泄漏；
- 遗留物：请求结束后临时目录为空，超过 TTL 的产物被删除。
